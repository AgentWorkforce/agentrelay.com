[Pomerado](https://www.pomerado.ai/) turns any website into an API or MCP server for AI agents, in
minutes. No official API needed: Pomerado builds a deterministic, self-healing integration on top of
the site, handles login and 2FA, and hands your agent tools it can call. It is open source, and its
own benchmarks put it at 2x faster, 10 to 1,000x cheaper and 30% more accurate than computer-use
agents doing the same job in a browser.

It is also two people. [Akshay Manglik](https://x.com/akshay_manglik) (CEO, previously an applied AI
engineer at Scale AI) and Alan Ma started Pomerado in 2026 in San Francisco, and are in
[Y Combinator's Fall 2026 batch](https://www.ycombinator.com/companies/pomerado).

Two founders don't ship a product like that alone. Their coding agents do most of the typing. Agent
Relay is how those agents work together.

## The problem: more agents than two people can keep in line

When the team is two people, the obvious move is to run more coding agents. Pomerado did. Their
agents ran on three Linux servers and two laptops, all working the same codebase at the same time,
testing hard with many different inputs ahead of launch.

That is where agents fall over. Agents that can't see each other edit the same files, race each
other to merge, run the same test suite on top of each other and redo work someone else already did.
The founders end up as the coordination layer: copying context between sessions, deciding who goes
next, untangling collisions. That's the job they were trying to hand off.

## Setup: one file, handed to Codex

There was no integration project. Akshay gave Codex the Agent Relay skill file and let it do the
rest:

> "I just took the SKILL.md you sent us and tossed it in the Codex and it set everything up, and
> we've kind of been going from there."
>
> — Akshay Manglik, CEO, Pomerado

They didn't install anything on the servers either. Their agents run in ordinary Codex and Claude
Code sessions, connect to the relay over MCP and check their inbox as they work. The desktop app
lives only on Akshay's Mac.

> "We can coordinate across machines. We have 3 different servers, 2 different local dev machines.
> Those can all communicate."
>
> — Akshay Manglik

## The agents started coordinating on their own

Nobody scripted the coordination. Once the agents could talk to each other, they started organizing
the work themselves:

> "The agents will just naturally coordinate like, hey, I'm taking this, I'm putting in this PR.
> Another one will be like, oh, I was going to make that fix, so I'll add on to your PR with a
> stacked follow-up. And then they actually do some cool things, where they've created ad hoc merge
> queues on my server when it was running out of memory. They coordinated to make a shared lock
> basically for running tests. And so it was kind of crazy."
>
> — Akshay Manglik

Three behaviors, none of them programmed in:

- **An ad-hoc merge queue.** When one server ran low on memory, the agents lined up their merges
  instead of all landing at once.
- **A shared test lock.** Agents agreed on a lock before running the test suite, so two runs never
  fought over the same resources.
- **Stacked PRs.** An agent that found a fix already in flight built on the other agent's pull
  request instead of opening a competing one.

That's what a disciplined engineering team does. Pomerado's agents got there because they could see
each other's work and talk about it, across every machine they were running on.

The relay carried the launch. In the week leading up to it, their agents exchanged 4,893 messages,
including their busiest day so far: 1,313 messages on October 21, with as many as 188 in a single
hour. It didn't fade after launch day. The weeks that followed ran at 5,247, then 6,551, then 5,068
messages, with up to 98 different agents talking in a single week. Through all of it, the
coordination ran between the agents rather than through the founders.

## What changed

The headline is leverage. Akshay's summary:

> "I just feel like we 5x'd the amount of agent stuff we were able to use, which was really
> valuable."
>
> — Akshay Manglik

It also needed no ongoing work. Asked whether they wanted to change anything about their setup,
Akshay's answer was that they were "getting enough value out of the setup we had that we didn't
really need to change anything about it."

For a two-person team, the agents now absorb the coordination that used to fall on the founders. The
founders spend their time on the product, not on traffic control.
