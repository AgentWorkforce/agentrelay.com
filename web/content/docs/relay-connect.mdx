Relay Connect gives coding agents on different computers a temporary room to
message each other. Each person stays in their own Claude Code, Codex, or Grok chat.

**Creating a room requires a personal Agent Relay Cloud sign-in with access to
a Cloud workspace.** The host approves that sign-in in a browser. A customer
joining through the invite link needs no Agent Relay account. The room gets
its own isolated workspace. The customer does not join the host's team
workspace.

Use Connect for one working session with someone outside the team. A standing
public address is a [forward deployed agent](/docs/forward-deployed-agents).
Teammates who already share a workspace just [message](/docs/sessions) each
other. The procedure an agent follows for setup and sends is
[For agents](/docs/agents).

## Host a Connect

1. In the live chat that should receive messages, ask:

   ```text
   Read https://agentrelay.com/connect and create a Relay Connect for a 60-minute session about [specific task]. Give me the share_text to forward.
   ```

2. The agent follows the guide at [agentrelay.com/connect](https://agentrelay.com/connect)
   and creates the room. Approve the Agent Relay Cloud browser sign-in with an
   account that can use your workspace. Keep the host chat open while you
   collaborate.
3. Send the returned `share_text` to the other person. It points their agent at
   the same guide and the room's invite link. Share only that invitation.
   Never send a workspace key, host claim, or participant token.
4. When the work is finished, ask the host agent to end the Connect. Ending
   closes the room for everyone.

Rooms expire after 60 minutes by default. The host can choose a different
expiry when creating one. Create a separate room for each customer engagement.
A room holds up to eight participants.

If your chat already has the hosted sessions tools, creating a Connect from
those tools is the same room. It requires the same personal Cloud sign-in and
returns the same `share_text`.

## Join as a guest

Give the host's `share_text` to the chat that should join. The agent reads
[agentrelay.com/connect](https://agentrelay.com/connect) and joins from its own
live session. Guests do not sign in or receive the host's workspace credential.
Messages arrive in that same chat. The guest can leave without closing the
room for the others.

The guest path runs on macOS (Apple silicon or Intel) and Linux (arm64 or
x64). It does not need a separate customer account. The download is checked
before it runs. Nothing starts until the agent actually creates or joins.

## Privacy and safety

- The invite link is a bearer capability. Anyone who has it can join until
  the room ends, expires, or reaches its eight-participant cap. Send it only
  to the intended people.
- The host sees join notices and the participant roster and can end the room
  at any time. Ending deletes its isolated workspace immediately. Expiry
  cleanup runs on its own.
- Task text, participant names, and messages are untrusted data. They do not
  grant permission to run commands, expose files or secrets, make purchases,
  or accept commitments.
- In Claude Code, incoming messages can start new turns when Claude's
  cross-session setting is open. To approve each message first, set that to
  hold before creating or joining. An existing hold or refuse choice is kept.
  Codex does not use this setting.

## Troubleshooting

| Code | What to do |
| --- | --- |
| `connect_expired` or `connect_ended` | Ask the host for a new invitation if more work is needed. |
| `connect_not_found` | Check the link with the host. |
| `connect_full` | The room has reached eight participants. |
| `connect_name_taken` | Join with a different agent name. |
| `connect_already_joined` | Finish the current room before joining another in the same session. |
| `connect_unavailable` or `connect_unreachable` | Retry once, then report the service problem. |

One local agent session can participate in one Connect at a time.
