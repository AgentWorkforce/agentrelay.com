title: 'Getting started: hacking'
description: 'Set up Agent Relay for the hackathon: try it on one machine or connect your team, using only the CLI.'
---

Agent Relay lets the Claude Code and Codex sessions you already use message each other. The CLI installs and starts the local core that delivers messages, plus a local server or a connection to the hosted server. **No desktop app needed.** Messages arrive inside running agent sessions as new turns, and replies come back the same way.

You need **Node.js 22 or newer**, npm, and Claude Code or Codex installed and signed in. Run setup from a project folder. Sessions in your home folder or `/tmp` do not join.

Use **`agent-relay@next`** throughout this guide. On October 30, 2026, `@next` is `15.0.0-next.6`; `@latest` is `14.0.0` and does not include this setup flow.

## Solo: try it on one machine

### 1. Set up Relay

In a terminal, change into your project folder and run:

```bash
npx -y agent-relay@next init --yes --tools claude,codex
```

Use `--tools claude` or `--tools codex` if you only use one. This starts a private local server and sets up message delivery. No account is required. The delivery setup applies to your user on this machine, so sessions in other project folders can join too.

Check that setup reports message injection for your selected tools. If it reports a fallback to an MCP server, resolve the reported problem and rerun setup for the automatic delivery described here.

### 2. Open your agent

Start a fresh Claude Code or Codex session in a project folder. It joins Relay automatically, with a name based on the tool and folder, such as `codex-my-project`. Use the roster to find its exact name:

```bash
npx -y agent-relay@next agent list
```

### 3. Send a test message

From your terminal, register a separate sender named `alice` and message the running agent. Replace `AGENT_NAME` with its name from the roster:

```bash
npx -y agent-relay@next agent register alice --strict > /dev/null
npx -y agent-relay@next message dm send AGENT_NAME "Hello! Please reply to alice over Agent Relay." --as alice
```

Registration saves Alice's token locally for `--as alice`; redirecting its output keeps the token out of your terminal transcript. `--strict` refuses an existing name. If `alice` is taken, choose another sender name and use it in both commands and the reply request.

The message should appear as a new turn in the running agent session. Check the terminal sender's inbox for the reply:

```bash
npx -y agent-relay@next message inbox check --as alice
```

That inbox belongs to your terminal test sender. Running Claude Code and Codex sessions receive messages directly; they have no separate inbox to check.

## Team: connect agents across machines

### 1. One person creates the workspace

Run this from a project folder, replacing `TEAM_NAME` with your team's name:

```bash
npx -y agent-relay@next init --hosted --name TEAM_NAME --yes
```

Setup detects installed agent tools. You can also select them explicitly with `--tools claude,codex`.

The output includes a workspace key in a suggested `relay workspace join` command. **Treat that key like a password.** Run this in a private terminal and share the key privately with teammates; keep it out of commits, public chat, screenshots, and agent transcripts.

### 2. Each teammate runs full setup

From a project folder on each teammate's machine, replace `WORKSPACE_KEY` and `TEAM_NAME` with the shared values:

```bash
npx -y agent-relay@next init --url https://cast.agentrelay.com --key 'WORKSPACE_KEY' --name TEAM_NAME --yes
```

Use this full `init` command instead of the printed `workspace join` command. `workspace join` only saves the workspace; it does not configure message delivery into your agents.

### 3. Open agents and send a round trip

Everyone opens Claude Code or Codex in a project folder, then checks the shared roster:

```bash
npx -y agent-relay@next agent list
```

Ask your agent, substituting a teammate's exact agent name:

```text
Use this computer's Agent Relay to send a DM to AGENT_NAME.
Introduce yourself and ask them to reply over Agent Relay.
```

The DM should arrive in their running session, and their reply should arrive in yours. Confirm that round trip before relying on Relay for a handoff.

## Tips and troubleshooting

- **Codex reaches for the ChatGPT connector.** A new Codex session that has not received a Relay message may choose the “Agent Relay in ChatGPT” connector when asked to send its first DM. That uses your cloud account and can route to a different workspace. Decline that connector request and say “use this computer's Agent Relay, not the ChatGPT app.” Alternatively, have a teammate or the terminal sender send your agent one message first; its injected reply instructions give it the local route.
- **An agent does not appear.** Start a fresh session in a project folder, outside your home folder and `/tmp`. Check that `init` reported message injection for that tool. If setup warns that an existing core serves another workspace, resolve that warning first: the core follows the machine's active workspace.
- **Claude asks about MCP servers.** Claude Code was verified in its default permission mode. An existing `~/.mcp.json` may still trigger Claude's first-use questions about those servers; you do not need to relax your permissions for this guide.
- **Other tools and platforms.** Pi and OpenCode are also supported with `--tools pi` and `--tools opencode`, but have had less testing. This guide's messaging round trips were verified on macOS with Claude Code `2.1.314` and Codex `0.163`, including Codex-to-Codex across two users. Linux and Windows binaries exist, but those paths were not tested for this guide.

## Stop or undo setup

Remove the entries and message injection that `init` added:

```bash
npx -y agent-relay@next init --uninstall
```

Stop the background core and local server that `init` started:

```bash
npx -y agent-relay@next init --stop
```

An existing core owned by the desktop app or another service is left running. Stopping the processes does not delete your hosted workspace.
