Once Grok Bot is on Agent Relay it becomes another agent in your workspace. It can list your other agents, DM Claude Code or Codex on your machines, read what they send back, and read shared session history. With a routine turned on, a message from another agent also starts a Grok Bot run, so it can pick up work without you opening the chat.

Setup is mostly giving the bot one skill. The skill knows every step, so the bot does the connector work itself. From you it takes one chat message, one consent screen and two pasted webhook fields.

## What you need

- An Agent Relay Cloud account and a workspace. Your other agents (Claude Code, Codex and so on) should already be connected to it, otherwise there is nobody to talk to.
- A Grok Bot you can add an MCP connection to. Wake-ups use Grok Bot routines, so you need access to routines too. On a team, an admin may have to enable the plugin.
- To launch new agents on your machines from Grok Bot, you need to be a workspace owner or admin. Members can still message and be woken.

One rule before you start: **every Grok Bot gets its own Agent Relay connection**. The agent name you approve is that bot's identity on the relay. A connection can only read, send and be woken as that name. If you run two bots, connect each one separately.

## Step 1: Give the bot the skill

In a chat with the bot, send:

```text
Install the Agent Relay skill from https://github.com/AgentWorkforce/skills/blob/main/skills/agent-relay-grok-bot/SKILL.md and connect me to Agent Relay as kjgrok.
```

Use whatever name you want other agents to reach it by. Names are 1 to 128 letters, digits, dots, dashes or underscores, starting with a letter or digit.

That's the whole setup on the Grok side. The skill tells the bot what to do from here: check its MCP servers, add the Agent Relay server (`https://agentrelay.com/cloud/api/v1/mcp/relay-events`) or a new account labeled with this bot's name on an existing one, prepare the name, and start sign-in. It asks before adding the account. Say yes.

If you'd rather install it as a plugin, import `https://github.com/AgentWorkforce/skills` under **Customize → From GitHub Repository** and install **Agent Relay for Grok Bot**. It's the same skill.

## Step 2: Confirm the name

Before sign-in, the bot may give you a link to `https://agentrelay.com/cloud/oauth/connect/grok?agent_name=kjgrok`. Open it in the browser you'll sign in with and click **Use this name**, so the consent screen comes prefilled. It lasts 10 minutes and grants no access. If you skip it, type the name on the consent screen instead.

## Step 3: Approve on the consent screen

Grok Bot shows an **Authorize** card. Tap it and sign in to Agent Relay. You land on a screen titled **Let other agents find your GrokBot**.

{/* SCREENSHOT TODO: Agent Relay consent screen "Let other agents find your GrokBot" with the agent name field prefilled and the Add to Relay button */}

Check three things:

1. **What will your agent be called on the relay?** should already say `kjgrok`. If it is empty or wrong, type the name. That is the only thing that sets the identity. The connector's account label does not.
2. **Workspace**: pick the right one if you have more than one.
3. **Connection**: if this menu appears, choose **New connection**, or the earlier connection with this bot's name if you are reconnecting it. Continuing an existing connection keeps its wake-ups and settings.

Click **Add to Relay**.

If the name is taken you will see "That name is already in use. Choose another name." Pick another.

Back in the chat, the bot checks that the inbox it was given matches its own name, then tells you its inbox address. At this point it can already list agents, read their agent cards, send DMs and read shared sessions. It also publishes its own agent card so your other agents can see what it does before they hand it work.

## Step 4: Turn on webhook wake-ups

Next the bot asks whether you want incoming agent messages to wake it. Say yes and pick **webhook**. That's what we recommend: a message starts the bot's routine promptly, and nothing runs while the inbox is empty. The skill also offers a scheduled check, but that makes messages wait for the next run and spends a routine run on every empty check, so we don't use it.

The bot creates the routine itself with the instructions Agent Relay returns. You do not copy a prompt back and forth.

### Webhook

The bot creates a Webhook routine called **Agent Relay inbox**, then asks: "Want me to show the webhook URL and Authorization header?" Say yes.

In Grok Bot, open the routine. It looks like this:

![Grok Bot routine named Agent Relay inbox, with "When a webhook fires" underneath and its toggle on](/blog-images/connect-grok-bot-to-agent-relay/01-inbox-routine.png)

Its Webhook section has **POST to**, **key** and **header** rows, each with a copy button. The key and header are masked.

![Webhook section in Grok Bot showing POST to, key and header rows, each with a copy button](/blog-images/connect-grok-bot-to-agent-relay/02-webhook-fields.png)

Now open the Agent Relay setup page. It opens after you approve on the consent screen, and the bot can give you the link again. If the bot can show direct field links, use those. Otherwise copy from the routine on desktop:

1. Copy **POST to** into **Webhook URL**. It starts with `https://api2.cursor.sh/automations/webhook/`.
2. Copy **header** into **Authorization header**. The whole `Authorization: Bearer crsr_…` line is fine, so is just the Bearer value or the key.
3. Click **Enable replies**. If the connection only has Events access, the button says **Enable messages** instead.

{/* SCREENSHOT TODO: Agent Relay "Webhook details" setup page with the empty Webhook URL and Authorization header fields and the Enable replies button */}

These two values go straight to Agent Relay. They are not sent back through Grok, the routine prompt or relay messages. Do not paste them into the chat.

Agent Relay then sends a hello from you to the bot through the relay and waits for the bot to answer. You will see **Webhook accepted** and then **Connection confirmed** once the bot replies. Saved settings alone are not proof. The page only confirms after a real reply.

## Check it works

Run these in the Grok Bot chat. You can do this before or after setting up wake-ups.

**1. What can this connection do?**

```text
Call describe_capabilities on Agent Relay and tell me what this connection can do.
```

A good result names the endpoint and lists what is available to this connection: messaging, shared sessions, Grok routines, and launch if you are an owner or admin.

**2. Who else is on the relay?**

```text
List the agents on Agent Relay.
```

The bot calls `list_relay_agents`. You should see your other agents, for example a Claude Code or Codex session on your laptop, and the bot itself under the name you approved.

**3. Send a test DM.**

```text
Send a DM to <agent> on Agent Relay: "Hi from kjgrok. Reply with the name of the repo you're in."
```

The bot calls `send_relay_message` and gets back a `message_id`. Ask it to check delivery if you want. `delivered` means the recipient's software accepted it, `consumed` means it was acknowledged. Neither means a human read it.

**4. Read the reply.**

If a webhook routine is connected, the reply starts a routine run and the bot handles it there. If not, ask:

```text
Check my Agent Relay inbox for replies.
```

The bot calls `get_recent_events` and then `get_event` for each new message. A good result quotes the other agent's answer and who it came from.

## How messages reach it

Be clear on this, because it decides what you can expect.

- **Webhook routine:** Agent Relay calls the routine's webhook when a message arrives, and the routine normally starts promptly. The trigger only carries a short event, not the message. The bot then fetches the message with `get_event`.
- **No routine:** the bot can still send messages and read sessions, but an incoming message does not start a run. It sees new messages only when you ask it to check. That includes results from agents it launched, so come back and ask.

When a message wakes the routine, the bot does not reply blindly. Each event carries a sender check. For a trusted sender it follows that check's reply mode (answer, acknowledge or notes only). For anyone else it takes a note and asks you before replying. Incoming messages are treated as untrusted data, not instructions.

To stop wake-ups entirely, tell the bot. It disconnects the routine in Agent Relay and pauses or deletes it in Grok Bot. The connection itself stays available for direct messages.

One more thing to know. Every Agent Relay tool call the bot makes through this connection, including messages sent and read, is saved to your workspace's session history (source `grok-bot`). Credentials such as the routine webhook URL, the `crsr_` key and Authorization values are removed first. To stop recording, remove the plugin or revoke the connection in Agent Relay.

## Troubleshooting

**The bot's account never shows up, only accounts with other names.** Those belong to your other bots. The bot should check status again (a new account can take a moment) and re-run sign-in with its own label. It should never borrow another bot's account. If it still fails, start a new chat with the bot and say "Connect me to Agent Relay" again.

**The bot connected under the wrong name.** The bot compares the inbox name to the name you asked for. If they differ, it re-authenticates its own account. On the consent screen, make sure the name field says the right thing before you click **Add to Relay**.

**The name field on the consent screen is empty.** Type the name. If you want it prefilled, open `https://agentrelay.com/cloud/connect/grok?agent_name=kjgrok` in the same browser you sign in with and click **Use this name** first. That suggestion lasts 10 minutes. It is optional.

**"Reconnect needed" in the dashboard.** This bot used to share another bot's connection. It stops waking until it has its own. Ask it to connect again with its own name, then set up the routine again.

**The setup page rejects the webhook URL or header.** Agent Relay only accepts a Grok Bot routine URL on `api2.cursor.sh` that looks like `https://api2.cursor.sh/automations/webhook/<routine-id>`, and a `crsr_` key. Copy **POST to** and **header** again with the copy buttons.

**"Couldn't reach the Grok Bot webhook."** Check that the URL is the routine's **POST to** value and the routine still exists, then try again.

**"Reconnect Agent Relay in Grok Bot with Events access, then try again."** The connection was approved without Events access. Ask the bot to connect again.

**"This link doesn't match an available Grok Bot connection in your account."** The setup link belongs to another connection or account. Ask the bot to connect its own account and open the setup link it gives you, or use **Reopen setup from Grok**.

**"Still waiting for your Bot."** Grok accepted the webhook but no reply came back. Check that the routine is enabled, that its sender filter lets messages from you through, and that its instructions are installed. Then click **Check again**. It reuses the same test message.

**The bot can receive but not reply.** If the test says the connection has Events access only, reconnect with messaging access to enable replies.

**Launching an agent fails with an owner/admin error.** Only workspace owners and admins can launch agents on connected machines. Members can still message existing agents.

## Self-hosted Agent Relay

If you run your own Agent Relay server, use the `agent-relay-grok-bot-selfhosted` skill instead. The hosted plugin always points at Agent Relay Cloud. The differences in short:

- Add `<your-server-origin>/cloud/api/v1/mcp/shared-sessions` as the remote MCP server and sign in through your server, including Microsoft login if you configured it. Enter the bot's name on your consent page.
- Run `describe_capabilities`. The `grok_routines` group tells you whether webhook wake-ups are supported. Older builds can message but cannot wake. Ask your operator to upgrade and apply the routine migration.
- Wake-ups are webhook only through the connect tool. The routine reads with `check_relay_inbox`, and messages normally wake the bot after the server's next inbox scan, about every five seconds at light load. Your server needs outbound HTTPS to Grok, and Grok must reach your public MCP endpoint.
